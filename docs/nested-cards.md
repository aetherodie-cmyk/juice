# JUICE-UI-001 · 巢狀卡片與原地展開 MVP

正式站獨立預覽：`https://aetherodie-cmyk.github.io/juice/nested-cards.html`。本機入口：`http://127.0.0.1:4200/nested-cards.html`。預覽頁不改寫正式白板，也尚未整合到正式白板畫布。

## 驗收步驟

1. 初次進入是隔離範例；依序點 **OMG → 異動 → 工作清單** 的箭頭，卡片在同一畫布內展開。
2. 展開 **驗收準備 · 共用引用**，兩處都會出現同一張 **Prototype 確認**。
3. 任一處直接改狀態；修改負責人後按 Enter 或離開欄位。另一處立即同步，不複製工作資料。
4. 點工作標題，完整標題、狀態、負責人、日期、說明在原卡內呈現。標題／日期／說明按「儲存詳細資料」後套用；未存的編輯保留在記憶體草稿中，不可誤以為已保存到檔案。
5. 展開後附近卡片向下避讓，連線端點跟著更新。按「全部收合」會恢復基準座標。拖曳把手或用方向鍵移動，可自行編排；滾輪平移、Ctrl／⌘＋滾輪縮放，底部可符合視窗。
6. 按 **儲存原型** 後重新整理，核對引用、資料、展開狀態與位置。也可下載原型 JSON，再從「匯入原型／白板副本」重開。
7. 每張巢狀卡可直接選「顏色」。卡片上的「操作」可移除此處引用，或刪除卡片本身；刪除前會要求確認。移除最後一處巢狀引用時，卡片會移到畫布上；刪除容器時，其失去所有位置的子卡片也會移到畫布上。

截圖裡的完成、Iris、10/25 都只當介面示意，沒有變成範例的真實狀態。初始狀態、負責人與日期均為待確認。

## 最小架構與資料邊界

原白板 `app.js` 把卡片、面板、選取、歷史與雲端同步放在同一閉包內；`Core.normalize` 又只保留既有格式的欄位。因此本次不在正式白板加入未知巢狀欄位，也不攔截其內部狀態或 localStorage。

新增獨立畫布入口，重用 `assets/core.js` 的白板驗證、內容清理與圖片限制，以及 `assets/pele-flow.js` 的安全流程預覽；延續相同色票、點陣背景、座標、卡片與連線呈現。所有原始白板資料保存在原型封裝的 `board`，正常白板輸入先驗證，再建立獨立副本；原物件不被改寫。

專用格式 `juice-nested-board` 第 1 版：

| 欄位 | 意義 |
|---|---|
| board | 輸入白板的完整原始 JSON，包含未知欄位、Classic／Flow Plus 區塊與連線；不將 normalize 的顯示結果覆寫回去。 |
| objects | 容器或工作各一筆，穩定 ID。容器可選 `purpose`（`general`、`project`、`feature`、`work-group`）；工作含 title、status、owner、dueDate、description、revision。 |
| memberships | 穩定引用 ID、containerId、objectId。多容器可指向相同工作；同一容器不可重複加入同一物件，循環引用拒絕。 |
| placements | 頂層畫布實例、物件 ID、寬度與基準座標；不是複製物件。 |
| boardPositions | 使用者在原型中拖動舊卡時的位置覆層；`board.cards` 的座標不變。 |
| ui | 畫布平移縮放，以及以完整引用路徑保存的容器／詳情展開狀態。不同引用各自決定是否展開。 |

儲存只用獨立 key `juice-nested-prototype-v1`，且僅在使用者按「儲存原型」時寫入。不讀寫 `sju-whiteboard-*`、`sju-workspace-meta`、IndexedDB 或 Google Drive。下載成功只代表交給瀏覽器，需自行確認檔案保存完成；瀏覽器容量不足時保留未存狀態，可改下載 JSON。

**匯出原白板** 只取出原始 `board`，所以與匯入時相同；巢狀物件及原型中的拖動需由「下載原型 JSON」保存。巢狀原型 JSON 不是正式白板的匯入格式，勿直接拿去覆蓋正式白板。

## 用途、層級與共用引用

容器的用途是可選標籤，不限制巢狀深度或父子種類。舊版 v1 原型沒有 `purpose` 時仍可載入，介面顯示「一般容器」，原始 JSON 不會只因開啟而被補寫。新容器可在建立時選用途；卡面選單可隨時修改，同一容器的所有引用會顯示相同用途。工作卡顯示「工作」而不需要另一個用途欄位。

容器與工作卡面會顯示目前引用位置的上層路徑，例如「OMG › 異動 › 工作清單」。同一工作在多個容器出現時，兩張卡面各顯示自己的路徑與醒目的「共用於 2 處」提示；它們仍指向同一工作 ID，修改狀態或負責人會同步。這些路徑是依 `placements`、`memberships` 即時計算的呈現資訊，並未複製工作或改變引用資料。正式白板整合方案見 [nested-cards-integration.md](nested-cards-integration.md)。

顏色只作視覺辨識，不代表固定業務狀態。原有色票可繼續讀取；使用者可替每張容器卡或工作卡選擇自訂色，保存為安全的 `#RRGGBB` 值。共用卡片的顏色也會同步。操作選單中的「移除此處引用」只處理這個位置，「刪除卡片」會移除這張卡的所有引用；刪除容器不連帶刪除子卡片。這些變更都要按「儲存原型」才會寫進本機存檔，亦可先下載 JSON 備份。

## 避讓規則

以 DOM 實際寬高建立矩形，先放展開卡，再處理受影響的鄰卡，沿 Y 軸向下推移並傳遞避讓。每次從基準座標重算，不累積位移；收合後因此可恢復。未受影響的既有卡片原本若有刻意重疊，維持原樣。手動拖動則明確改變原型的位置基準。

這不是全圖排版或智慧路由：不重新整理原有布局、不做水平最佳化，也不保證長箭頭避開每一張中間卡片。幾何位移即時完成，避免成長中的容器在移動動畫期間壓住鄰卡。查看較高的工作詳情時，會微調畫布平移，讓可見區呈現資料；不跳頁。

## MVP 限制與測試

- 可新增容器／工作、加入或移除引用、刪除巢狀物件及修改顏色；尚無調寬 UI。原白板唯讀卡片仍不可在此頁刪除。
- 原白板卡片內容唯讀，支援拖動位置覆層與完整內容檢視，不提供正式白板全部編輯操作。自訂圖示仍顯示原點陣圖；部分內建圖示以通用符號呈現，原資料不變。
- 長文字／超過四個區塊的舊卡預覽有明確提示，可查看完整內容；流程圖預覽依既有 Pele CDN 可用性，失敗保留原文，不影響資料保存。
- 上限：原白板 200 張卡／1000 條線、巢狀物件 200、引用 400、頂層畫布實例 100、可見引用 500、深度 8 層，原型 JSON 20 MB。本機原型不自動截掉超限資料，會拒絕載入或展開。
- 未做多人共編、權限、Roadmap、甘特、Agent API、正式資料遷移；未驗收 Safari 實機或觸控雙指縮放。

測試命令：`npm run check`、`npm run test:nested`。獨立測試伺服器在 4203，不重用其他 checkout 的服務。單元與瀏覽器測試涵蓋巢狀路徑、共用資料、循環拒絕、避讓與還原、JSON 原樣往返、保存重載、舊資料與儲存隔離、文字安全、新增與引用、窄畫面。既有功能回歸使用 `npm run test:workspace:regression`；整體結果仍需區分已知白板剪貼簿案例。

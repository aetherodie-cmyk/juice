# 聚思白板（Juice）

純前端個人白板。卡片、區塊編輯、連線、標籤、參考圖片、地圖擷取與 AI JSON 收件匣；不包含 AI 模型服務或後端資料庫。

## 開始使用

每次進站先顯示白板選擇畫面：

- **繼續上次編輯**：顯示名稱、儲存位置、卡片數與上次保存時間；不需要登入即可使用本機內容。
- **Google Drive**：在開始畫面直接登入、選擇白板或重新整理清單。登入後可將新白板存到 Drive。
- **建立新白板**：輸入名稱並選擇這個瀏覽器或 Drive。本機具名白板各自保存在 IndexedDB，可從本機清單切換，不會只覆蓋同一張畫布。
- **匯入**：從 JSON 備份建立本機白板。

點編輯畫面左上角的名稱可返回白板選擇器。切換前會完成目前白板的待存作業、保存本機白板並建立復原快照；同步失敗會保留目前內容並取消切換。

Drive token 不會跨重新整理保存。上次的 Drive 畫布會標示為「本機副本」，繼續編輯不會自動寫回 Drive；需重新登入、選擇雲端白板才會連線。載入遠端前仍會備份目前副本；若有未同步內容，請先匯出保留。

瀏覽器網站資料被清除後，本機白板清單與內容也會一起消失，重要資料請定期匯出。

## 開發與驗證

直接以靜態伺服器開啟，不需要建置：

```sh
python3 -m http.server 8080 --bind 127.0.0.1
```

瀏覽 `http://127.0.0.1:8080`。瀏覽器儲存依 origin 區分，換 hostname、port 或瀏覽器都不會自動帶入資料；請先匯出 JSON。`file://` 的本機儲存行為依瀏覽器而異，Google 登入應使用設定好的 HTTP localhost 或 HTTPS 網址。

測試使用 Node.js 22+、Python 3 及 Chromium：

```sh
npm ci
npx playwright install chromium
npm run check
npm test
```

測試以模擬的 Google 授權與 Drive HTTP 回應驗證，不存取真實帳號。GitHub Checks 只執行驗證，不執行部署。

## 檔案結構

- `index.html`：唯一應用畫面。
- `whiteboard.html`：舊網址轉址至同目錄 `index.html`，避免兩份程式分歧。
- `assets/styles.css`：畫面樣式。
- `assets/core.js`：HTML 允許清單、資料格式／容量驗證、IndexedDB、寫入序列與 HTTP 錯誤／逾時處理。
- `assets/app.js`：白板編輯、儲存協調、Drive、本機檔案、收件匣、地圖及畫面事件；以功能段落組織，共用同一份狀態。
- `tests/whiteboard.spec.cjs`：瀏覽器回歸測試。
- `docs/maintenance.md`：資料格式、同步限制、OAuth、復原與發布流程。

## 手機操作

窄螢幕（640 px 以下），或 1024 px 以下的觸控裝置，使用手機版操作：

- 底部放「新增、搜尋、移動、框選、更多」，不需要橫向捲動頂部工具列。
- 瀏覽模式下點卡片開啟編輯；單指拖曳平移畫布、雙指縮放。空白處雙點不再新增，避免誤觸，改用「新增」。
- 按「移動」後拖曳卡片；先用「框選」逐張點選或拖曳空白處框選，再切換移動，可整批移動。
- 搜尋比對標題、區塊內文與標籤，點結果直接開啟卡片；最多先列出 50 筆，可輸入關鍵字縮小範圍。
- 編輯頁佔滿可見畫面，固定顯示「完成」、複製、刪除與保存狀態。畫面高度不足時先收起顏色／形狀，按「外觀」即可展開。
- 上方保存狀態可點擊，Drive 模式可儲存／重新授權；其餘工具從「更多」開啟。手機橫向仍保留觸控操作，回到大螢幕恢復桌面工具列。

鍵盤調整使用 Visual Viewport API，支援手機安全區域並避免限制頁面縮放。自動測試涵蓋 Chromium 觸控模擬、雙指縮放與縮小可見高度；實際 iOS／Android 的鍵盤、瀏覽器工具列與切換 App 行為仍應進行實機驗證。

## 復原、重做與複製

- 選取單張或多張卡片後，按工具列／浮動工具列的「複製」，或使用 `⌘/Ctrl+D`，會向右下偏移 32 個白板單位建立副本；保留內容、標籤、樣式與卡片間的相對位置。
- 多選複製會複製選取卡片彼此的連線；不會複製指向未選卡片的連線，也不複製群組外框。副本使用新的卡片／區塊／連線 ID，AI 審核來源不會沿用。
- 工具列「復原／重做」，或 `⌘/Ctrl+Z`、`⌘/Ctrl+Shift+Z`（亦支援 `Ctrl+Y`），可復原整批移動、複製、刪除及其他白板內容操作。
- 在文字輸入欄位中，快捷鍵維持瀏覽器原本的文字復原／複製功能。要復原白板操作，可先離開輸入欄位或點工具列按鈕。
- 畫布平移、縮放與選取不列入復原紀錄。輸入同一文字欄位的連續編輯會合併為一步；復原後進行新內容操作會清除重做紀錄。
- 復原紀錄只存在目前頁面的記憶體，最多 50 步且受 16 MB 預估容量限制；重新整理、切換白板／儲存來源或審核收件匣後清除。復原只處理目前白板內容，不回復 Drive 垃圾桶或收件匣的外部操作。

## 框選與批次移動

- 點工具列「框選」，在空白處拖出選取框；與框相交的卡片會被選取。
- 拖曳任一已選卡片，整批卡片保持相對位置一起移動。
- 不切換模式也可按住 Shift 拖曳空白處框選，並加入原有選取。
- 點空白處取消選取；Esc 取消進行中的框選，再按 Esc 可退出框選模式。
- 關閉「框選」後，空白處拖曳維持畫布平移；縮放與雙指操作維持原本行為。

## 資料與同步

本機主資料使用 `localStorage` 的 `sju-whiteboard-v2`，可讀取舊 `sju-whiteboard-v1`。輸出 schemaVersion 3，保留舊鍵名方便搬移既有資料。圖片內嵌於 JSON；單次匯入上限 20 MB，實際瀏覽器儲存容量可能更小。

本機容量不足時仍嘗試 Drive／檔案同步。Drive 與本機同步檔採單一目的地，切換前先保存、保留 IndexedDB 快照。JSON 匯入建立本機白板，不覆蓋原 Drive 檔。

每次寫回先讀取遠端並比較載入基準；不同則停止覆寫並保存兩份內容。單一瀏覽器的寫入依序執行，避免先後顛倒。這不是多人即時協作系統，仍應避免同時編輯。

「復原備份」可下載最近 20 筆 IndexedDB 快照。重要內容仍需定期使用「匯出」下載獨立 JSON。登出不會清除本機資料；共用電腦請在備份後清除網站資料。

## 部署

既有 GitHub Pages 從 `main` 根目錄發布；推送到 main 可能更新正式站。沒有編譯步驟，須一起發布 HTML 與 `assets/`。本次維護不變更 Pages 設定。發布前請依維護文件完成人工授權測試及備份。
